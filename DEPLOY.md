# Deploying nossteal.mail for real mail (scuffedmail.online)

Your laptop can run everything for development, but **live internet mail needs a
small public server** with outbound/inbound **port 25** open. Home ISPs almost
always block port 25 (both directions) and reject mail from residential IPs, so
sending/receiving from your PC will not work reliably. This guide puts the mail
pieces on a cheap VPS while keeping DNS at Vercel.

---

## 0. What runs where

| Piece | Where | Port |
|-------|-------|------|
| PostgreSQL | VPS (or managed DB) | 5432 (internal) |
| API server (`npm run start`) | VPS | 4000 |
| Inbound SMTP receiver (`npm run mailserver`) | VPS | **25** (public) |
| Web app (`next start`) | VPS or Vercel | 3000 / 443 |
| DNS | **Vercel** (your domain) | — |

Vercel hosts the **web app and DNS only** — it cannot run the SMTP receiver, so
the mail server must live on the VPS.

---

## 1. Get a VPS with port 25

Pick any provider that allows SMTP / port 25 (many block it by default — ask
support to open it, or choose one that allows it):

- Hetzner Cloud (cheapest, port 25 on request), DigitalOcean, Vultr, OVH, Linode.
- Ubuntu 22.04/24.04 LTS is assumed below.
- Note the server's **public IPv4** — call it `SERVER_IP`.
- Ideally set **reverse DNS (PTR)** for `SERVER_IP` -> `mail.scuffedmail.online`
  (done in the VPS provider's panel). Missing PTR = mail gets rejected as spam.

Open the firewall:

```bash
sudo ufw allow 22,25,80,443,3000,4000/tcp
sudo ufw enable
```

## 2. Install runtime on the VPS

```bash
# Node 20+
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs postgresql

# PostgreSQL role + db (matches DATABASE_URL below)
sudo -u postgres psql -c "CREATE ROLE nossteal LOGIN PASSWORD 'CHANGE_ME';"
sudo -u postgres psql -c "CREATE DATABASE nossteal_mail OWNER nossteal;"
sudo -u postgres psql -d nossteal_mail -c "CREATE EXTENSION IF NOT EXISTS \"uuid-ossp\";"
```

Copy the project up (git clone or `scp`), then:

```bash
cd nossteal.mail/server
npm install
```

Create `server/.env` on the VPS:

```
PORT=4000
DATABASE_URL=postgres://nossteal:CHANGE_ME@localhost:5432/nossteal_mail
JWT_SECRET=<run: openssl rand -base64 48>
CREDENTIAL_ENCRYPTION_KEY=<run: openssl rand -base64 32>
SEED_ADMIN_USERNAME=<your-admin-username>
SEED_ADMIN_PASSWORD=<a-strong-password>
SEED_ADMIN_EMAIL=admin@scuffedmail.online
MAIL_SMTP_PORT=25
```

> Use a **fresh** `CREDENTIAL_ENCRYPTION_KEY` here. Secrets (DKIM keys, mailbox
> passwords) are encrypted with it — if it differs from where they were created,
> they can't be decrypted. Since you'll re-create the domain/mailbox on the VPS,
> a new key is correct.

Build + migrate + seed:

```bash
npm run build
npm run migrate
npm run seed-admin
```

## 3. Run the services (systemd)

Create `/etc/systemd/system/nossteal-api.service`:

```ini
[Unit]
Description=nossteal.mail API
After=network.target postgresql.service

[Service]
WorkingDirectory=/opt/nossteal.mail/server
ExecStart=/usr/bin/node dist/index.js
Restart=always
EnvironmentFile=/opt/nossteal.mail/server/.env

[Install]
WantedBy=multi-user.target
```

Create `/etc/systemd/system/nossteal-smtp.service` (binding port 25 needs root
or `CAP_NET_BIND_SERVICE`):

```ini
[Unit]
Description=nossteal.mail inbound SMTP
After=network.target postgresql.service

[Service]
WorkingDirectory=/opt/nossteal.mail/server
# mailserver script uses tsx; for prod you can compile it too. tsx is fine:
ExecStart=/usr/bin/npx tsx src/mailserver/smtpReceiver.ts
Restart=always
EnvironmentFile=/opt/nossteal.mail/server/.env
AmbientCapabilities=CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now nossteal-api nossteal-smtp
sudo systemctl status nossteal-smtp   # confirm "listening on port 25"
```

The web app can stay on Vercel (point `NEXT_PUBLIC_API_URL` at
`https://api.scuffedmail.online`) or run on the VPS with `npm run start` behind
nginx. Put nginx/Caddy in front of the API for HTTPS if the web app is remote.

## 4. DNS at Vercel

In **Vercel -> scuffedmail.online -> DNS Records**, add (Name is relative to the
domain). The three TXT records were generated by the app and are shown on the
**Domains** page; the two below (A + MX) are what make mail actually flow:

| Type | Name | Value | Priority |
|------|------|-------|----------|
| A | `mail` | `SERVER_IP` | — |
| MX | `@` | `mail.scuffedmail.online` | 10 |
| TXT | `@` | `v=spf1 ip4:SERVER_IP -all` | — |
| TXT | `nossteal._domainkey` | `v=DKIM1; k=rsa; p=...` (from Domains page) | — |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:postmaster@scuffedmail.online` | — |

Notes:
- **SPF**: use `v=spf1 ip4:SERVER_IP -all` (not the bare `-all` the app defaults
  to) so your own outbound passes SPF. The app signs with DKIM regardless, and
  DMARC passes on DKIM alignment, but authorizing the IP is cleaner.
- **DKIM**: re-create the domain in the app *on the VPS* (new encryption key =
  new keypair) and copy that DKIM TXT value, or migrate the existing key. Use
  whatever the VPS **Domains** page shows.
- Recreate the mailbox (e.g. `admin@scuffedmail.online`) on the VPS instance.

## 5. Verify

```bash
# From the VPS or anywhere:
dig +short MX scuffedmail.online
dig +short TXT scuffedmail.online
dig +short TXT nossteal._domainkey.scuffedmail.online

# Send yourself a test from Gmail to admin@scuffedmail.online -> it should
# appear in the inbox. Check the SMTP service log:
sudo journalctl -u nossteal-smtp -f
```

- Send **to** a Gmail/Outlook address from the app and confirm it lands (check
  the "show original" headers: SPF=pass, DKIM=pass, DMARC=pass).
- Use https://www.mail-tester.com — send it a message and aim for 9–10/10.
- Warm up slowly; keep DMARC at `p=none` until delivery is consistently clean,
  then tighten to `p=quarantine` / `p=reject`.

---

## Troubleshooting

- **Outbound stuck / timeouts**: provider hasn't opened port 25 egress — open a
  ticket. Test with `telnet gmail-smtp-in.l.google.com 25`.
- **Mail lands in spam**: almost always missing **PTR/reverse DNS** or SPF/DKIM
  misalignment. Fix PTR first.
- **"550 No such mailbox"**: create the native mailbox in the app for that exact
  address (local part is case-insensitive).
- **Can't decrypt secrets after moving**: the `CREDENTIAL_ENCRYPTION_KEY`
  differs from when they were saved — recreate the domain/mailbox on the new host.
